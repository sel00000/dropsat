# 결정 기록 (DECISIONS)

> 팀이 정한 것과 이유를 남겨서, 사람도 에이전트도 같은 질문을 반복하지 않게 한다.
>
> - **맨 아래에 추가만** 한다. 지난 결정을 바꿀 땐 그 항목을 고치지 말고 새 항목을 추가한 뒤, 옛 항목 상태를 `폐기 → D-0xx`로 바꾼다 (상태 변경은 lead).
> - 상태: `확정` · `제안`(확정 전까지 기본값으로 따른다) · `미정` · `폐기`
> - 에이전트는 `확정`·`제안` 결정과 다르게 구현하지 않는다. 바꾸고 싶으면 사용자에게 제안한다.
> - 번호가 겹치면 나중에 합치는 쪽이 번호를 올린다.
>
> 새 항목 형식:
>
> ```
> ### D-0xx · 한 줄 제목
> - 상태: 제안 · 날짜: YYYY-MM-DD · 누가: 역할(이름)
> - 내용:
> - 이유:
> ```

### D-001 · 팀 맥락은 저장소 파일로 공유한다
- 상태: 제안 · 날짜: 2026-11-08 · 누가: Claude (협업 구조 세팅)
- 내용: 모든 에이전트의 공통 규칙은 `AGENTS.md`, 팀 맥락은 `team/`에 둔다. Claude Code용 `CLAUDE.md`는 AGENTS.md를 불러오기만 하고 규칙을 따로 쓰지 않는다.
- 이유: 에이전트는 세션끼리 대화를 공유하지 못하고, 팀원마다 다른 에이전트를 쓸 수 있다. AGENTS.md는 대부분의 코딩 에이전트가 자동으로 읽는다.

### D-002 · `out/`의 시뮬레이션 결과를 기준 데이터로 고정한다
- 상태: 제안 (강력 권장) · 날짜: 2026-11-08 · 누가: Claude
- 내용: 웹사이트의 DROPSAT-1 수치는 저장소에 커밋된 `out/` 파일에서만 가져온다. `out/`을 지우거나 덮어쓰는 명령(`make clean`, `make run`, `make plot`의 기본값)은 쓰지 않는다.
- 이유: 같은 기본 설정으로 다시 돌려도 환경에 따라 결과가 달라진다. 2026-11-08 클라우드 환경(GCC 13.3)에서 다시 돌리자 EWOD 실험 #2가 `STUCK`에서 `OK`로 바뀌고, 교신별 수신 프레임 수와 비콘 수(66 → 64)도 달라졌다. 팀원마다 다른 데이터를 보면 화면과 발표 수치가 엇갈린다.

### D-003 · 폴더 구조
- 상태: 제안 · 날짜: 2026-11-08 · 누가: Claude
- 내용: 웹 앱은 `web/`, 데이터 수집·변환 스크립트는 `data/`, 디자인 산출물은 `design/`에 둔다. 웹이 읽는 데이터 파일은 `data/`의 스크립트로 `web/public/data/`에 만든다. 위성 SW(`fsw/`, `sim/`, `tests/`, `tools/`)는 그대로 둔다.
- 이유: 위성 SW 빌드와 분리하고, 역할별 담당 경로가 겹치지 않게 하려고.

### D-004 · Git 작업 방식과 Live Share 사용 범위
- 상태: 제안 · 날짜: 2026-11-08 · 누가: Claude
- 내용: 각자 자기 PC에 clone 하고 `<역할>/<주제>` 브랜치에서 작업하며, 하루 2번 이상 PR로 main에 합친다. VS Code Live Share는 함께 보는 시간(회의, 통합, 같이 디버깅)에만 쓰고, 그때 에이전트는 호스트 한 명만 쓴다.
- 이유: Live Share 게스트 PC에는 파일이 없어 게스트의 에이전트가 파일을 읽지 못하고, 한 폴더를 에이전트 여럿이 동시에 고치면 서로 덮어쓴다.

### D-005 · 웹 기술 스택
- 상태: **미정**. 킥오프에서 정한다. 정하기 전에는 어떤 에이전트도 웹 프로젝트를 새로 만들지 않는다 (서로 다른 스택으로 두 번 만들어지는 것을 막기 위해).
- 정할 것: 프레임워크, 차트 라이브러리, 스타일 방식, 배포처(GitHub Pages·Vercel·Netlify 등)
- 후보: Vite + React + TypeScript / Next.js / 순수 HTML·JS
- 추천 (Claude): Vite + React + TypeScript. 정적 사이트라 배포가 단순하고, 차트 라이브러리와 에이전트 지원이 가장 넓다. 팀이 더 익숙한 쪽이 있으면 그쪽이 우선.
